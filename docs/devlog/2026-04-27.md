### 設計判断（codex 助言反映）

- **`neutral` / `skipped` も fail 扱い**: GitHub Actions 依存関係上は成功扱いだが「main HEAD が Pages に反映済み」の証明にはならないため、保守的に fail させる
- **空配列 fallback は維持**: ユーザー指示「現状維持」を尊重し、CF 側 GitHub App 障害等の極端ケース用セーフティネットとして残す。ただし常用される設計ではないため `is_fallback=true` フラグを強く可視化（artifact suffix + job summary 警告文）
- **将来検討事項（次回 spec 改訂候補）**: codex は「空配列 fallback は schedule 限定 degraded mode にすべき。push trigger では fail させる方が CI 健全性が高い」と助言。今回はスコープ外として devlog にメモのみ

旧 spec `20260426-lighthouse-ci-two-tier` の物理ファイル（`openspec/proposals/20260426-*/spec.md`）は phase-2-dryrun ブランチにのみ存在し、本ブランチからは触れない。新 spec の `supersedes` frontmatter で関係を明示し、`tasks.json` の `active_specs` から旧 ID を除外。
